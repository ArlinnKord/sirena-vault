# Аэрофлот — рерутинг

⚠️ Применимо ТОЛЬКО к Аэрофлоту. Рерутинг = изменение условий/маршрута по выписанному билету. Физически переоформление делает сама а/к — агент считает доплату и пишет письмо в а/к (шаблон — во внутренней документации).

## Последовательность
1. `ЭБ#<номер>` — открыть билет (у Аэрофлота только так — в GUI «заблокирован»). Взять: старый тариф, старые таксы, маршрут/даты.
2. Наличие нового рейса: `1<ГГ><ГГ><ДДММ>-SU` (напр. `1ШРМПЛК1010-SU`). Обращать внимание на класс и место в салоне.
3. `ОЦ#1` — оценка маршрута (1 = номер рейса). Здесь смотреть стоимость подкласса (тариф нового перелёта).
4. Вернуться к экрану наличия, выбрать рейс и место, внести пассажира из билета: `-КИО <ФИО> <ДР>+<ПОЛ>`.
5. `ТМ` — тарификация (новый тариф и новые таксы).
6. Расчёт доплаты для счёта клиенту:
   - (новый тариф) − (старый тариф) = **доплата по тарифу**
   - (новые таксы) − (старые таксы) = **доплата по таксам**
   - + **сбор за обмен** (обычно 3–5 тыс., точную сумму — из правил тарифа)
   - Итого → выставить счёт клиенту.
7. Клиент согласился и оплатил → письмо в а/к (переоформление делает она).

## Расчёт стоимости одного сегмента (ТКП, наша таблица такс)
Специфичная тема для частично использованных билетов (см. черновик «Общие заметки»):
1. `ЭБ#<номер>` — скопировать полностью данные билета в нашу таблицу такс (раздел ТКП, первая строка). Нужны тарифы по сегментам.
2. Скопировать первый (уже использованный) перелёт из результатов обработки → в Сирене в новое окно → в передачу.
3. Сравнить тариф, который клиент пролетел; искать в нашей таблице такс: X = round trip, T = one way. Нужна разница между T → вычесть её из оригинального билета = цена тарифа второго сегмента без такс.
4. Таксы: из нашей таблицы такс (ТКП) скопировать информацию по таксам → в Сирену. Искать рейс; из старых общих такс вычесть таксы сегмента: из RI вычесть RI, из YR — YR, остальные по логике.

## Альтернативный путь — расчёт справками вне брони (с доски, 11.09.2026)
Те же цифры (тариф сегмента + таксы), что берём из нашей таблицы такс, можно получить прямо в Сирене — без PNR. Маршрут в примере: Москва → Анталья (MOW→AYT), а/к SU.

1. **Стоимость (тариф):** `Т<МОВ><АЙТ><дата вылета>-SU*<подкласс>/AAA?БР=NB`
   Пример: `ТМОВАЙТ19НОЯ26-SU*G/AAA?БР=NB`
   - `Т` — тарифная справка вне PNR (формат `Т<ГГ><ГГ><дата>-<АК>*<подкласс>`; буква команды — **одна `Т`**, дальше слитно коды городов). Не путать: `ТМ` без городов — это автооценка маршрута внутри PNR, другая команда;
   - `19НОЯ26` — дата вылета; `*G` — подкласс; `/AAA` — категория пассажира;
   - `?БР=NB` — разбивка тарифов по брендам, бренд NB (эконом basic у Аэрофлота).
2. **Таксы:** `ИС<МОВ><АЙТ><ДДММГГ>-SU*AAA`
   Пример: `ИСMOWAYT191126-SU*AAA` — справка сборов на пару пунктов (формат `ИС<ГГ><ГГ>-<АК>`).
3. **Сбор а/к** (за обмен) — в правилах тарифа: `ТМ/П` → `ТП01/16`. Указан в евро → перевести в рубли: `ПВ/<сумма>/ЕВР/РУБ`.

Обозначения `X` = round trip / `T` = one way — это **колонки нашей таблицы такс**, не часть команды (см. шаг 3 выше). Нам нужна разница по `T` (one way).

> [!warning] Не проверено (записано с доски, объяснение прослушано)
> - `=NB` трактую как бренд; `*AAA` в `ИС` — как категорию пассажира (в памятках справок стоит `/ААТ`) — сверить на пульте;
> - сам рерутинг по-прежнему делает а/к: агент считает доплату и пишет письмо.

## Ещё способ — фиктивная бронь на пульте ЮТэйр (с доски, 29.09.2026)

Если нужно посчитать **тариф и таксы нового рейса** и цифрами из справок неудобно — можно оценить рейс «по-настоящему», через фиктивную бронь:

1. Выйти на наличие нового рейса и сделать `ОЦ` (выбор рейса → список подклассов с ценами, как выше).
2. **Собрать фиктивную («призрачную») бронь на пульте ЮТэйр** (ЮТ). Она повторяет структуру настоящего обмена, но заполняется так, чтобы Сирена посчитала разницу маршрутов:
   - создать бронь и внести **первый сегмент — ненастоящий** (имитирует старый / уже пролетевший участок билета);
   - внести **имя** — случайного пассажира (в расчёт идёт только структура перевозки, человек не настоящий; ⚠️ что бронь не уходит в отчётность — сверить на пульте);
   - добавить **второй сегмент — настоящий** (новый рейс/тариф, на который считаем доплату);
   - **`ТМ`** — тарификация всей брони: получаем то же, что дал бы реальный обмен — это **расчёт «призрачного обмена»** (сравнение старого и нового маршрута внутри одной брони).
3. Сравнить полученные тариф и таксы с цифрами из билета клиента (старый тариф / уже пролетел) — **разница и есть доплата** (тариф + таксы, см. шаг 4 выше).
4. По полученным цифрам посчитать доплату и **отправить клиенту расчёт** (доплата по тарифу + по таксам + сбор за обмен, см. шаг 6 выше).

⛔ **Сам обмен/рерутинг по-прежнему делаем не мы** — переоформляет авиакомпания. Если клиент согласен и оплатил — пишем **письмо в а/к** (шаблон — во внутренней документации).

> [!warning] Не проверено на пульте
> Способ записан с доски 29.09.2026; порядок шага 2 (ненастоящий сегмент → имя → настоящий сегмент → `ТМ`) уточнён по нашим записям 08.10.2026 — на пульте не прогоняли. Смысл: ЮТ используется как «технический» пульт, чтобы прогнать настоящую тарификацию рейса без рабочей брони Аэрофлота. Сверить: проходит ли тарификация рейса SU на пульте ЮТ и не «прилипает» ли фиктивная бронь к отчётности.

## NUC и ROE — как читается расчёт тарифа (с доски, 11.09.2026)
`NUC` — универсальная валюта, используется между а/к. **Порядок расчёта: `NUC × ROE` = сумма в ЕВРО**, затем ЕВРО → рубли командой пульта.

Пример строки расчёта тарифа:
```
РАСЧ ТАР :MOW 5G EVN138.77 5G MOW115.64NUC254.41END ROE0.864730
```
Как читать:
- по плечам: MOW→EVN `138.77` + EVN→MOW `115.64` = `254.41` NUC (сумма плеч сходится с итогом — проверено);
- `5G` — код на плече (похоже на перевозчика, не расшифрован — сверить);
- `ROE0.864730` — коэффициент: 254.41 × 0.864730 ≈ **220.00 ЕВРО**.

Дальше ЕВРО → рубли через пульт: `ПВ/<сумма>/ЕВР/РУБ` (пример: `ПВ/120/ЕВР/РУБ`).
Таксы считаем через нашу таблицу такс, окошко **ТКП** (см. шаг 4 выше).
